# Operations

The public product name is Config manager and residential manager. Existing `config-repair` filesystem and service names are retained for upgrade compatibility.

## Paths and services

| Purpose | Path/service |
|---|---|
| Panel and collector | `config-repair.service` |
| Ordinary validation | `config-repair-prober.service` |
| Residential investigation | `config-repair-egress.service` |
| Country refresh | `config-repair-country-update.timer` |
| Ads exit network evidence refresh | `config-repair-network-update.timer` |
| Releases and runtime cores | `/opt/config-repair/` |
| Encrypted SQLite data and blobs | `/var/lib/config-repair/` |
| Encryption key and origin | `/etc/config-repair/panel.json` |
| Fresh-install login | `/etc/config-repair/access.txt` |
| Nginx virtual host | `/etc/nginx/conf.d/config-manager-residential.conf` |

Back up the database, its WAL (if present), immutable blob directory, panel configuration including the encryption key, and the matching release together while all three application services are stopped. Keep this backup private. Losing the key makes encrypted state unreadable. Never upload these files to GitHub.

## Upgrade and recovery

Schema 55 identifies VMess shares that put a cipher name in the transport TLS field. Residential results for those original shares show an explicit unsupported reason. The ordinary diagnostics can exercise the proposed interpretations separately. The upgrade preserves the original receipt and any matching structural failure when it corrects a previously scheduled compatibility review. An incompatible local listener can be identified before trying another version of the same core.

A due, source-owned retirement confirmation can take a maintenance turn after seven other maintenance grants while it remains overdue. The missed-grant count survives a worker or panel restart. On the existing third maintenance turn, a previously verified route whose proof has expired can renew ahead of a newly withheld input that has never qualified. Country guards and accepted-route safety checks keep their priority.

Schema 54 retains the source of a pending delivery-failure confirmation across natural withdrawals and restarts. A previously unaccepted config with proven ownership can receive up to three additional leases. Only independent, measured failures inside the confirmation window count toward retirement. Missing measurements retain the original deadline on an existing healthy receipt. The upgrade also checks actionable verdicts against the original input and assessment time. Conflicting country evidence or a mismatched runtime can withhold publication while a fresh measurement is pending. The source response cache tracks the identities in each received body, including a body deferred by the source count check.

A compatibility follow-up is available for a sole, empty unsupported receipt when the authenticated original now yields two runnable variants. The original assessment remains in the ledger. An enabled source or a verified withdrawal supplies custody. The first real measurement closes this follow-up and a lost lease can use one more grant. If an unassessed original has gone missing, a currently committed alias can take its place after byte and identity verification. Its next assessment runs against its own hash.

Schema 53 keeps the ordinary first-probe queue position on the collector identity. A changed display name or encoding can replace the raw input and still keep its turn within its source. The last attempted time also survives that replacement. The clock begins when the ordinary queue admits the identity. Eligibility still comes from current source membership or a retained first assessment, subject to the existing source, network and operator controls.

Schema 52 recovers older source withdrawals that predate the first-assessment backlog. It verifies the committed representative, sole surviving source for those bytes, source and job revisions, absence of prior claims or results, administrative and network exclusions, and the authenticated original file. Its separate indexed queue offers one historical input per ten first-assessment grants under continuous demand. Either queue can borrow available capacity. A newly received copy rejoins the normal first queue using its existing identity and lease. The historical recovery counts appear separately in the Residential dashboard and in `accounting.archive_recovery`. In `accounting.first_assessment.first_results_5m`, the `historical` count is the subset of `withdrawn` that completed on an archive lease. A promoted input is attributed to its membership at completion. Migration reads the candidate blobs once. Rehearse using both the matching vault and its key, and include them in the stopped-service backup.

The ordinary queue also records its dispatch turns durably. During contention, three first grants reserve the next grant for a due repeat probe. It uses the recorded identity assessment to tell a new job from a returning config. A scheduled retry after a local worker failure keeps its first-probe priority.

Schemas 50 and 51 preserve the first assessment across source changes. In the Residential queue, the dispatcher records consecutive first and maintenance grants in the same transaction as each lease. When both classes are ready, two consecutive grants normally give the other class its next turn. A due, previously proven residential route within 60 seconds of expiry or already overdue can take a third maintenance grant. A waiting first assessment then gets the fourth opportunity. This applies even when a single worker slot receives all available permits. Untouched inputs are ordered by original identity registration time. After a worker interruption or local failure before measurement, the input stays pending. When its retry becomes due, peers waiting since its last grant go first. A retained withdrawal marker receives urgent maintenance priority while its measured confirmation window is open. The panel shows ready, running and delayed work and the oldest ready input for both current and withdrawn configs. Its five-minute first-result counter starts when schema 50 is installed.

The ordinary prober retains the original raw representative until the first assessment completes, even if a source naturally rotates during the lease. It records source service order for ready first probes. Source replacement, administrative exclusions and existing publication checks continue to apply. A fully parsed source response that is too small to replace an existing subscription can still contribute new identities to both test queues. Failed or unfinished fetches follow the collector retry path. To rehearse an upgrade, use a matched schema-49 database, blob and key copy with the previous release. Compare a fixed set of outstanding identity keys to completed first receipts after restart, including withdrawals. Live source totals alone can change as links refresh.

Schema 49 re-evaluates saved datacenter holds using the original assessment time, raw input and probe receipt. Only a repeated hosting exit on a demonstrably separated Ads flow can retain the datacenter label. Shared exits and insufficient comparisons have separate diagnostics. A historical replay cannot extend route, health or country validity. Identities needing new evidence have a persistent review record with a budget of two expedited follow-up leases. Previously verified Residential entries retain their regular health maintenance after those attempts. The scheduling history grants no publication rights. The panel reports pending and exhausted reviews alongside the confirmed rejection count. The coverage table shows Residential eligibility before country selection and publication after the country filter for each current source. Use its total row for the unique count across active sources.

Before upgrading a schema-48 installation, rehearse schema 49 on a separate copy of the stopped database, blobs and matching key. Reopen that copy and verify that the second startup preserves the review counts and deadlines. Keep the matched schema-48 release and backup. Recovery after resumed collection must account for subsequent writes.

Schema 48 keeps the first recorded Residential assessment for each collector identity across refetches and worker restarts. Existing assessments survive the migration. In the Residential panel, the current source counts distinguish assessed, awaiting, excluded, and missing identities. Each active source also has its own breakdown. Accepted routes remain eligible for maintenance after withdrawal from a source. An inconclusive renewal before any route observation can reuse the remaining validity of the previous receipt. Its original expiry still applies.

The Residential panel provides a separate raw subscription for identities with a recorded hosting or mixed exit on their Ads route. Its count and download apply the same inclusion rules. Deleted, paused and safety-blocked entries are withheld. The country selector controls the four Residential subscriptions. Treat subscription URLs as access credentials. Preserve a matched schema-47 backup before the upgrade. Schema-47 binaries cannot reopen a schema-48 database.

Schema 47 preserves pending first assessments when a committed source rotates or its artifacts expire. An input shared by several sources keeps one test representative. The first committed worker receipt releases the pending record. The migration preserves assessment history and starts recording withdrawals at upgrade time. For a rollback rehearsal, retain a stopped schema-46 copy of the database, blobs, key and matched release. Open a separate copy with schema 47 and verify the stored sources, accepted outputs and completion counts. Exercise the synthetic withdrawal, restart and evidence fixtures using `go test ./internal/panel -run 'Test(WithdrawnFirstAssessment|FirstAssessmentMigration)'`. Restore the matched schema-46 backup in an isolated directory to rehearse the previous version. The previous binary rejects a schema-47 database. Recovery to the earlier snapshot requires accounting for subsequent writes.

The automatic installer owns only its marked installation. It will refuse an unmarked older deployment or architecture mismatch. Upgrade preparation downloads/verifies and builds the new release before stopping services. A stopped backup is made for a changed release; `panel.json`, existing password and key are preserved. A failed download/build leaves the current services untouched. After a failed cutover inspect systemd logs and preserve the current database: do not blindly restore an older snapshot over resumed collector writes.

For an unmarked historical deployment, use a planned migration: take the shared `/var/lock/config-repair-deploy.lock`, stop the panel and every old worker including `config-repair-smart`, back up key/data/blobs and old units together, validate the new binary against a copy, remove the retired Smart unit and its owned sandbox resources, install the new release, then start only the three services above. Do not run a schema-40 binary against schema 41. Preserve ordinary sources, exclusions, rotations, Residential evidence and revocation ledgers. Reclaim removed-feature blobs only after confirming that no retained table references their hash.

The schema-41 cleanup retains only migration references to the retired names. Those references are necessary to remove historical tables safely; they do not register an API, UI, worker or generator. Original user-provided raw configurations can still contain Xray balancing fields; the importer preserves their bytes and does not turn them into a Smart product feature.

## Network and TLS

The installer enables IPv4 forwarding in a dedicated sysctl file. Probe sandboxes use uniquely named nftables tables; no host firewall is flushed. Existing provider or host forwarding/firewall policies may need operator adjustment. Only open the configured HTTPS port to intended administrators. The internal panel port 18191 must remain loopback-only.

Self-signed TLS permits initial encrypted administration but subscription clients generally need a publicly trusted certificate. Replace `/etc/config-repair/tls.crt` and `tls.key` with the full chain/private key for the configured hostname, retain restrictive private-key permissions, and reload Nginx. Never solve certificate rejection by disabling verification in exported VPN configurations.

If hosted behind NAT, pass `CMRM_HOST` on first install. Changes to the public hostname or port require coordinated origin, certificate and Nginx changes; the installer rejects accidental changes on rerun.

If another application already listens on TCP 18443, choose a free port with `export CMRM_PORT=18444` before the first installation. Do not stop the other application to free its port. The internal loopback port 18191 must also be available.

The country updater preserves last-good datasets and retries daily. Inspect `/var/lib/config-repair/country/update-status.json` if the installer reports incomplete country data. No healthy/Residential result is manufactured when evidence is missing.

The installer queues the first Ads exit network update in the background. Its separate systemd timer refreshes the local index every six hours. Check `systemctl list-timers config-repair-network-update.timer` for the next run and `journalctl -u config-repair-network-update.service` for source errors. To refresh data after correcting a source, run `systemctl start config-repair-network-update.service`. The updater writes `/var/lib/config-repair/network/egress-network.sqlite` by atomic replacement. The probe reads this snapshot locally. A verified hosting exit on a separated Ads flow withholds Residential publication for that identity. A hosting observation shared with the ordinary route is attributed to that route. A hosting observation without sufficient comparisons can withhold the affected profile while another fully verified profile remains eligible. Missing network ownership data leaves the network type unknown. Existing confirmed holds require fresh evidence to clear. Schema 46 reuses fresh route, health and country evidence from earlier versions without requiring a network backfill. See the [Ads exit network policy](ADS-EXIT-NETWORK.md).

To extend verified coverage, record operator-reviewed allocations in `/etc/config-repair/egress-network-allocations.json`, owned by `root:config-repair` with mode `0640`. The top-level object has `version` equal to `ads-exit-network.v1` and an `allocations` array. Each record supplies a CIDR `prefix`, `kind` (`access` or `hosting`), `provider`, expected origin `asn`, independent usage `source`, HTTPS `evidence_url` documenting that prefix’s use, and an expiring `valid_until` in Unix milliseconds. Refresh with the network update service. The snapshot build and worker independently check routing evidence. An ASN-wide customer assumption cannot establish access use.

Operators with licensed local MaxMind data can enable a supplementary driver. Install the distribution's `python3-maxminddb` package and set `/etc/config-repair/egress-access-mmdb.json` to a JSON object with `connection` and `asn` entries. Each entry contains an absolute `path` and a 64-character lowercase `sha256`. Use GeoIP2 Connection Type for `connection` and GeoIP2 ISP or GeoLite2 ASN for `asn`. Keep the manifest and databases root-owned and unwritable by group or other users. After a licensed database update, update the checksum. The driver requires current data, a positive cable/DSL or cellular classification, and independent matching routing evidence. No key or licensed database is distributed with this project.


## A download shows zero bytes

The bootstrap prints the source URL and transport for each attempt. It downloads directly from GitHub codeload first, then tries the official archive URL if needed. Downloads abort after 20 seconds below one byte per second, use an eight-second connection timeout, and share a total retry budget (120 seconds for source; 300 seconds per pinned dependency). Automatic transport selection falls back to IPv4 with HTTP/1.1. Set `CMRM_IP_VERSION=4` or `6` before running the README command to select an address family explicitly. This does not change system DNS or IPv6 configuration. TLS verification and dependency checksums remain mandatory.

If the budget expires, the installer reports the failed URL and stops; fix DNS/HTTPS reachability and rerun the same command. The bootstrap download in the README also has connection, idle-transfer and total-attempt limits. A transient stall does not by itself establish an IPv6 or application fault. Compilation is announced separately with a `[build]` line and can legitimately take several minutes.

Schema42 adds independent datacenter/CDN classification and rotation tables. The panel owns two bounded background network workers; no additional systemd service or Nginx route is required. Group subscriptions live under the existing `/subscription/` location. Use matched backups before migration; schema41 binaries cannot reopen schema42. See [DATACENTER.md](DATACENTER.md).
